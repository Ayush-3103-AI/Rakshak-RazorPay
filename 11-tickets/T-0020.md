# T-0020 — Release hygiene: LICENSE, the missing interface spec, and a dependency for cut work

**Day:** Sat 29 Aug (runs now; touches no number) · **Risk:** low effort, **all three are panel-visible** · **Cuttable: no** · **Depends on (blocked by):** none — can start immediately

## Why this ticket exists

Three defects that survive into a **public, graded** repo and that no ticket owned. Found 2026-08-29 in a board audit. None can affect a measured number; all three are visible to anyone who opens the repo before reading a line of the code.

## Build — 1. `LICENSE`

`pyproject.toml` declares `license = { text = "MIT" }`. **There is no `LICENSE` file.** A public repo that declares a licence it does not ship is the first thing a careful reader notices.

- Add the MIT licence text, correctly attributed and dated 2026.
- Confirm it does not conflict with the data terms: nothing under `data/` is committed, BAF is CC BY-NC-SA 4.0 and **not vendored**, Online Retail II is CC BY 4.0. The repo licences the **code**; `data/external/*.manifest.json` carries each dataset's own terms.
- Note the trap T-0015 recorded, so nobody repeats it: BAF's GitHub `LICENSE` is Apache-2.0 and covers *their code*, not the data.

## Build — 2. `09-interfaces.md`

`CLAUDE.md`'s context table lists it. T-0006b and other tickets name it as the source of the `Scorer` contract. **It does not exist** — the contract actually lives in `eval/harness.py`'s module docstring, which is what T-0006b used. A README citing an interface spec that is not in the repo is a panel-visible defect.

- Write it, from the contract as implemented — do not invent an interface the code does not honour.
- Cover: the `Scorer` signature and what a scorer may return; the `Split` object and its guarantees; `CostParams` and the units of every field; the `PolicyResult` contract including `binding_constraint`; the `results/` artifact schemas that T-0014 consumes.
- State that `eval/harness.py`'s docstring was the de-facto contract until this file existed, and which is now authoritative.

## Build — 3. Drop `pymoo`

`pyproject.toml` declares `pymoo>=0.6.2` for T-0009 (NSGA-II frontier), which was **cut** on 2026-08-28. A declared dependency for work that does not exist implies a multi-objective frontier the repo does not have.

- Remove it, and confirm nothing imports it.
- ADR-0004 already records the decision and the cut; add a line there noting the dependency was removed on 2026-08-29 so the ADR and the manifest agree.

## Done when

- `LICENSE` exists, is MIT, and does not contradict any dataset's terms
- `09-interfaces.md` exists, describes the contract **as implemented**, and every ticket citing it now resolves
- `pymoo` is gone from `pyproject.toml`, nothing imports it, and ADR-0004 records the removal
- `python -m pytest` and `python -m ruff check src tests` still pass
- **No results artifact changes.** This ticket cannot move a number; if one moves, something else is wrong

## What this ticket must NOT do

- Do not write an interface spec that is more ambitious than the code. If the implementation and the desired contract differ, the file records what is true and the gap is raised, not papered over.
- Do not touch `src/` beyond removing a dependency that nothing imports.
