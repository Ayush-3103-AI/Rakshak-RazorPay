# T-0002 — Spike: hand-written HMM core + minimal recovery proof

**Day:** Sat 29 Aug · **Risk: A-002 — the highest unretired risk in the project** · **Cuttable:** no — spine · **Depends on:** T-0001

## Context to read
`07-math.md` (HMM section), `08-pseudocode.md` (forward/backward/Viterbi/Baum-Welch), FR-012 and FR-013 in `06-requirements.md`.

## Why this ticket exists before the real generator
Building the full generator and feature pipeline (T-0003, T-0004) before knowing whether a hand-written HMM can recover latent states **at all** risks two days of work on a dead foundation. This ticket is a deliberate spike: the smallest possible harness that answers the one question that can kill the project, as early on Saturday as possible — not at EOD, when there's no time left to pivot.

## Build
- `src/rakshak/models/hmm.py` — forward, backward, Viterbi, Baum-Welch, **all computation in log space** (FR-012)
- A throwaway toy generator fixture (3–4 states, small N, hand-constructed ground-truth path) — **do not reuse this in T-0003**, it exists only to unblock this test
- `tests/test_hmm_recovery.py` — Adjusted Rand Index between recovered and true state sequences, after optimal label permutation, must exceed 0.5 (FR-013)
- A brute-force enumeration check of all state paths on a tiny 3-state/5-observation case, compared against Viterbi's output

## Done when
- Baum-Welch log-likelihood increases monotonically across iterations (test asserts this)
- Viterbi output matches brute-force enumeration exactly on the tiny fixture
- ARI > 0.5 on the toy fixture after label permutation

## If this fails
**Stop. Do not patch around it.** This is kill criterion K1. Raise a DESCEND to Phase 2 per `CLAUDE.md`'s working agreements — the fallback is LightGBM-on-windowed-aggregates + the cost layer, still a valid Track 02 submission, but without the explainability differentiator. Log the failure honestly in `LOGBOOK.md`'s `SURPRISE` field.
