# T-0015 — Procure public datasets and build an empirical calibration profile

**Day:** unscheduled — see Sequencing note · **Risk:** low technically, **high on scope** · **Cuttable:** yes, but it is the only ticket that puts real-world-derived numbers anywhere near the generator · **Depends on:** none (data-only; does not touch the model)

## Why this ticket exists

Every number in the repo today is measured on data this repo authored. T-0004's K1 failure is
credible *because* a failure on your own generator is hard to explain away — but no success
measured this way is fully credible, because a win partly measures how well the model learned
our own assumptions. This ticket procures the only external evidence available and turns it
into a **calibration profile**: a set of empirical marginal distributions the generator can be
re-grounded on in T-0016.

## The constraint that bounds this ticket — read before scoping

`06-requirements.md:28` and ADR-0007 already establish: **no public merchant-sequence dataset
with merchant-level risk labels exists.** Public fraud data is transaction-level or
application-level. Do not go looking for one and do not let this ticket drift into a hunt for
it. What public data can legitimately supply is **marginals and rates**, not sequences or
labels:

- amount distributions by category
- inter-arrival times / velocity distributions
- hour-of-day and day-of-week seasonality
- realistic fraud/chargeback/refund base rates
- payer↔merchant bipartite structure where present

Anything beyond that is out of scope for this ticket and probably for this project.

## Build — `src/rakshak/data/`

- **Survey and select.** Evaluate at minimum: BAF (Feedzai, NeurIPS 2022), IEEE-CIS Fraud
  Detection, the ULB credit-card dataset, PaySim, and Sparkov. For each record: what it actually
  contains, its granularity, its **licence and redistribution terms**, its size, and precisely
  which of the marginals above it can and cannot inform. Reject the ones that cannot.
- **Licence check is a gate, not a footnote.** BAF is CC BY-NC-SA 4.0 — verify this at source.
  A non-commercial or share-alike licence may be fine for evaluation inside a git-ignored
  `data/` directory and unacceptable to vendor into the repo. State the terms explicitly and
  record what they permit. If a dataset's licence forbids the use we intend, drop it and say so.
- **Downloader** with a fixed seed, resumable, writing to `data/external/`. `data/` is
  git-ignored except manifests (`.gitignore`), so **the dataset must never be committed.**
- **Manifest** at `data/external/*.manifest.json`: source URL, retrieval date, SHA-256, row
  count, licence, and the subsample seed if subsampled. This is the provenance artifact — the
  README cites it.
- **`profile.py` → `results/calibration_profile.json`** — the deliverable T-0016 consumes.
  Committed, human-readable, every figure carrying which dataset and which column produced it.
  This file, not the raw data, is what crosses into the generator.

## Done when

- At least one dataset downloaded, hashed, manifested, licence recorded and verified at source
- `results/calibration_profile.json` committed, with per-figure provenance
- A written statement of what the profile does **not** cover — the sequence and label structure
  that remains entirely synthetic. This goes in the README next to the profile's numbers.
- Determinism: re-running the profiler on the same manifest reproduces the JSON byte-identically
- Nothing under `data/` is committed. Verify with `git status` before closing.

## Relationship to T-0012

T-0012 (BAF validation) already downloads BAF. **T-0015 absorbs that download step**; T-0012
keeps the validation run. If both are built, T-0012 depends on T-0015's downloader rather than
fetching BAF a second time.

## Amendment — 2026-08-28, added during the post-T-0006 spec revision

**This ticket gained one deliverable and a new role in the plan.**

### New deliverable: the profile-vs-generator marginal diff

`results/calibration_gap.md` — a direct comparison of every marginal in
`results/calibration_profile.json` against the corresponding hand-chosen value in
`src/rakshak/generator/`. Per marginal: the empirical value, the generator's value, and
the divergence.

This is not a nice-to-have appendix. It is the artifact that makes the project's deepest
limitation **measured rather than merely admitted.** "We did not calibrate the generator"
is a weak README line. "Here is exactly how far our generator's amount distribution,
inter-arrival times and refund base rates sit from BAF's, per marginal" is a strong one,
and it is the honest-measurement axis Track 02 scores.

### New role: this ticket is the decision gate on T-0016

T-0016 is no longer scheduled work. It is **conditional on this ticket's diff**:

- **divergence small** → T-0016 is a cheap parameter swap and the re-measurement is fast.
  Take it if slack survives.
- **divergence large** → `results/calibration_gap.md` is published as the stated
  limitation and **T-0016 does not run.** A partially recalibrated generator measured on
  a distribution nobody can characterise is worse than an honestly uncalibrated one —
  T-0016's own text says so.

Either branch ships a committed artifact. That is what converts the T-0016 scheduling
gamble into a measurement.
