**Day:** Sun 30 Aug (evening) → Mon 31 Aug · **Risk:** low, mechanical · **Cuttable: yes — ranks below T-0013/T-0018/T-0020/T-0021/T-0019, see BOARD.md cut order** · **Depends on (blocked by):** none — can start immediately, parallel to T-0022a

## Context to read

`project-context/14-spec-blackswan-and-drift-survey.md`. `src/rakshak/eval/splits.py`'s `load_split()`. `src/rakshak/eval/harness.py`'s `run()` (already takes a `results_dir` override — this ticket adds the matching data-path override).

## Why this ticket exists

T-0022c needs to score a second dataset (`data/synthetic_shock/`) through the exact same fitting/scoring logic that produced every existing number, so that a bug fixed once is fixed for both tracks and the shock track can never silently diverge from the primary scoring code. Today `load_split()` hardcodes `TRANSACTIONS_PARQUET` / `STATE_PATHS_PARQUET` from `config.py`.

## Build

- Add optional `transactions_path=` / `state_paths_path=` parameters to `load_split()`, defaulting to the current `TRANSACTIONS_PARQUET` / `STATE_PATHS_PARQUET` constants so every existing call site is unaffected.
- Add a matching optional pass-through to `harness.run()` (alongside its existing `results_dir` override).
- Do not reimplement any fitting or scoring logic — the same `evaluate_model` / `MODEL_REGISTRY` path must run regardless of which dataset it's pointed at.

## Done when

- `load_split()` and `harness.run()` accept the new overrides; calling either with no arguments behaves exactly as before.
- Regression test: `harness.run(seed=42)` with **no overrides** produces a `summary.md` byte-identical to the current committed one — proves this seam is inert on the primary path.
- A second test runs `harness.run()` pointed at an arbitrary alternate parquet pair (a copy of the real data is sufficient for this ticket — T-0022c is what points it at the real shocked dataset) and confirms it scores successfully.
- `python -m pytest` and `python -m ruff check src tests` still pass.

## What this ticket must NOT do

- Must not change any default behavior of `load_split()` or `harness.run()`.
- Must not touch `MODEL_REGISTRY`, `evaluate_model`, or any model-fitting code.
- Must not itself generate or reference `data/synthetic_shock/` — that's T-0022a's and T-0022c's job.
