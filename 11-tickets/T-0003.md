# T-0003 — Full synthetic generator: 4 typologies + adversarial slow-ramp

**Day:** Sat 29 Aug · **Risk:** medium · **Cuttable:** no — spine · **Depends on:** T-0001

## Context to read
FR-001 through FR-006 in `06-requirements.md`. ADR-0007 (hybrid data strategy) if referenced in `03-landscape.md` or `04-patterns.md`.

## Build — `src/rakshak/generator/`
- Configurable merchant count + horizon, seeded, emits a parquet of transactions (`merchant_id`, `timestamp`, `amount`, `payer_id`, `method`, `mcc`, `is_refund`, `is_chargeback`) plus a separate ground-truth table of per-merchant state paths **with transition timestamps** (FR-001, FR-003)
- Merchant population heterogeneity: AOV spans ≥2 orders of magnitude, monthly volume spans ≥2 orders of magnitude, ≥6 distinct MCC segments (FR-002)
- Four labelled typologies (FR-004):
  - `BUST_OUT` — legitimate history → hard volume ramp → vanish
  - `LAUNDERING_ENDPOINT` — normal tickets, abnormal payer graph (many payers, no repeats, no organic returns)
  - `CATEGORY_DRIFT` — silent shift in ticket-size/timing profile to a different business category
  - `REFUND_COLLUSION` — merchant + small payer set cooperate to extract value via refunds/chargebacks
- Fifth **adversarial** typology, `SLOW_RAMP` (FR-005): designed to be hard to detect. **Do not tune detection to catch this — it exists to be reported as a failure mode.**
- Module docstring + note (also goes in README §Scope and Safety): this generator is an evaluation artifact for testing detection, not a fraud toolkit — produces no output usable against a live system (FR-006)

## Done when
- Schema test + row-count assertion + determinism test (same seed → identical hash) pass
- Heterogeneity spread test passes (FR-002 acceptance)
- Per-typology fixture test: each of the 5 typologies is separably detectable by at least one emission
