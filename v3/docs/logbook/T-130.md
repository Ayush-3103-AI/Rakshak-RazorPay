## Built
- `src/rakshak/eval/splits.py`
  - `SplitBoundaries` — day ranges 0-119 / 120-149 / 150-179, validated contiguous and
    ordered at construction. A gap silently drops days; an overlap leaks them. Both are
    now constructor errors rather than a comment.
  - `merchant_fold()` — blake2b keyed with a fixed salt. Deliberately **not** Python's
    `hash()`, which is per-process randomised: a fold built on it would move merchants
    across splits between runs and quietly invalidate every cross-session comparison.
  - `assign_rows()` — a row lands in split `S` iff its merchant's fold is `S` **and** its
    day falls in `S`'s span. Everything else is `None` and excluded. This is the strict
    reading of "both constraints simultaneously", and it makes "no merchant_id spans two
    splits" true by construction, not by a later assertion.
  - `available_labels(as_of, labels=DEFAULT_LABEL_PATH)` — the single door. Applies
    `label_available_at <= as_of`, drops `is_censored`, refuses a naive `as_of`.
  - `label_coverage(as_of)` → `LabelCoverage(n_merchants, n_available, n_censored,
    n_pending, n_positive)` with `prevalence` and `coverage` properties. Censored rows are
    excluded **and counted** — that count is the whole difference between honest and
    convenient.
- `tests/unit/test_splits.py` — 24 cases on synthetic fixtures, including the defining
  domain case: a day-100 fraud with a day-175 chargeback is invisible at day 120 and
  visible at day 179.
- `tests/gates/test_label_access.py` — the AST scan, plus **negative controls** that run
  each detector against a synthetic offending module inline, so the scan can be shown to
  fail rather than merely to pass.

## Surprised
**The AST scan's first version would have failed on `store.py`'s docstring.** `store.py`
names `label_available_at` in prose precisely to point at the gate and say "not here" —
the opposite of opening a second door. A raw-text scan cannot tell the two apart, so the
detector had to become AST-aware and skip docstring `Constant` nodes. The general shape:
a leakage scan strict enough to be worth running is strict enough to punish the
documentation that explains the rule. Two exemptions were needed and both are principled
— `schemas.py` *defines* the column name (that is its job) and docstrings are prose.

Second, smaller: `zip(spans, spans[1:], strict=True)` is a bug, not a safety net. `strict`
means "same length", and adjacent-pair iteration is by definition length n-1. It raised on
import at module scope, so it failed loudly — but the reflex to add `strict=True`
everywhere is worth noting as one that has an exception.

## Scan coverage — what it cannot catch
Written into the module docstring of the gate test so it travels with the code: a runtime-
assembled path, a semantically-wrong-but-syntactically-legal re-export of an
`available_labels(include_censored=True)` frame, anything via `getattr`/`importlib`/
concatenated SQL, and any code outside `src/`.
