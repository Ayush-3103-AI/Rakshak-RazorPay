## Surprised

**1. The NFR-04 diagnosis in LIMITATIONS.md §2 was right about the cause and wrong about the
size, and fixing the cause did not fix the problem.**

The entry said 7,091 B measured, gap ≈ 120 B of pickle framing × 28 objects, "a
serialization problem, not a feature problem". Two things turned out otherwise:

- 7,091 B was measured before the trailing windows had filled. At steady state the pickled
  state is **13,145 B**. A state measured before its rings fill is measured below its real
  size, and that is the flattering number.
- Packing removes the framing and lands at **9,634 B**. But the *zero-framing float64
  floor* — every scalar at natural width, no tags, no lengths, no class names — is
  **9,734 B**. The packed form is already below the naive floor, because narrowing histogram
  counts to uint32 buys more than the tag bytes cost.

So there is nothing left to serialize away. 9.6 KB is what the 28 features hold. The two T2
histogram features are 4.1 KB of it between them. **NFR-04 is a feature-count problem
wearing a serialization problem's clothes**, and the fix is in `tier2.py`, not in `state.py`.
The 4,096 B assertion is kept live as `xfail(strict=True)` with a live 10,240 B regression
fence beside it; the budget was not raised.

**2. `@dataclass(slots=True)` breaks zero-argument `super()` in a method of the class it
decorates.**

`FeatureState.__init_subclass__` needs to register each state type with the codec's
allowlist. Written the obvious way it raises `super(type, obj): obj must be an instance or
subtype of type` on the first subclass — because `slots=True` does not mutate the class, it
*replaces* it, and the `__class__` cell in the discarded original's methods still closes over
the discarded original. The hook is correct without the `super()` call (there is no
cooperative chain above `object` here), and the replacement re-enters the hook, which is
what makes the surviving entry the slotted class callers actually hold. Comment left at the
site; the next person will hit this on any slotted base with a `__set_name__`-style hook.

**3. Loading state costs more than computing on it.** The NFR-03 breakdown at 10,000
merchants: 15.5 s deserializing packed state, 4.7 s ingesting 80,000 events, 2.5 s for
stage 0 + stage 1. The whole feature layer is a fifth of the sweep. The pure-Python codec is
~6× slower than pickle in both directions — a real trade for 27% of the size, named in
`state.py` with the upgrade path (one numpy structured buffer per feature type, not a return
to pickle). NFR-03 passes at 1.3× so it was left alone.

**4. The cascade's margin is smaller than expected, and it grows with the register, not with
today's numbers.** Reading all 28 features for all 10,000 merchants is ~7.1 s of compute
against the cascade's 2.5 s. A single-stage design fits the 30 s budget today. What it does
not do is *stay* fitting: the four T2 divergences are three quarters of a full read, and the
fifth feature of that kind is what turns a comfortable sweep into a missed window. The
argument for the cascade is the derivative, not the level, and the writeup should say so
rather than claim a 12× speedup nobody measured.

## Broke

- `from conftest import ...` does not work for a second test suite. `pythonpath` puts
  `tests/parity` on the path, so a bare `import conftest` from anywhere resolves to *that*
  conftest — which is why `tests/gates` can import `assert_parity` from "conftest" at all.
  A perf conftest importing its own helpers by that name broke collection of both suites the
  moment they were collected together. Fixed the way the parity suite already fixed it: a
  uniquely named module, `perf_budgets.py`. Worth knowing that
  `pytest tests/parity tests/gates` has always failed collection for the same reason —
  `make parity` and `make gates` are separate targets, so it has never bitten.
