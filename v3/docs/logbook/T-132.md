## Surprised

**1. Capacity, not the cost model, is what makes the system selective — and I had that
backwards.** `test_capacity_is_a_ceiling_not_a_quota` failed on its first run: I built it
with 98 merchants at score 0.001 and expected the selector to ignore them. It alerted on 50.
The arithmetic is right and my intuition was wrong — at `review_cost = ₹250` and
`p_catch = 0.80`, a merchant with a 0.1% chance of fraud on ₹5L of exposure has an expected
loss of ₹500 against a ₹350 expected review cost, so reviewing it is **profitable**. The
economic "worth it" test excludes almost nobody at these parameters; K is doing essentially
all of the filtering. Two consequences worth carrying into Lane D:
  - the cost-asymmetry sweep matters more than expected, because at high ratios the HOLD
    branch changes but the REVIEW branch barely moves;
  - the P@K number will be driven by the *ranking*, not by the threshold, which is a point
    in favour of reporting gap-to-oracle over an absolute savings figure.

**2. I got the hand-checked knapsack instance wrong twice and the solver was right both
times.** Capacity 5 over weights 1/2/3: I wrote "take all three" (total weight 6). Capacity
4: I wrote "take 2+3" (weight 5). The DP is 20 lines and it was correct on the first run;
the "obvious" expected values were not. Noted because the reflex when a test fails is to
suspect the code, and here the test was the wrong half twice in a row.

**3. `oracle.py` imports `metrics.py`, so `metrics.build_eval_result` cannot import the
leakage assertion at module scope.** Resolved with a deferred import inside the function,
with a comment saying why. The alternative — splitting the cost matrix into a fourth module
purely to break a cycle — is more files for no behaviour.

## Broke
- `select_actions` originally took `loss` as its exposure input in the sweep, which handed
  the decision layer the true `true_loss_amount_inr`. That is perfect foresight about
  magnitude, it inflates every rung, and it can let one beat the oracle. `sweep_cost_asymmetry`
  now takes an explicit `exposure_inr` argument documented as "must be feature-derived,
  never true loss". This was found by reasoning about the leakage assertion, not by a
  failing test — the test would have been green.
- `ruff B008`: `ActionPolicy()` as a function default. Hoisted to a `DEFAULT_POLICY`
  singleton.
