## Decisions worth reviewing

**An enforced lock mismatch is rendered, not raised.** `verify_lock()` hard-fails on
`eval_module_sha256`. The report catches that and renders a `LOCK MISMATCH — READ THIS
BEFORE ANY NUMBER BELOW` block above every table instead of crashing. A reader handed
nothing learns nothing; a reader handed a table headed LOCK MISMATCH learns the one thing
that matters. Unenforced drift is listed with both hashes.

**Row provenance disagreement is a refusal.** `eval_lock_sha`, `open_count` and `git_sha`
are per-row; if any two rows disagree, `ProvenanceError` and no file is written. The
scenario-config hash and the seeds come from `EVAL-LOCK.json`, which cannot disagree with
itself. Demonstrated in three tests, one per field, plus one that the refusal leaves no
half-written `results_v2.md` behind.

**No timestamp in the output.** Re-rendering the same rows produces a byte-identical file,
so a diff on `docs/results_v2.md` is always a diff in the results. The git sha and the lock
sha are the provenance; a `generated_at` would only add noise.

## Surprised

**A gap in the sweep looked exactly like a flip in the ranking.** The first version compared
the per-scenario rung ordering as a tuple. Rung 0 was scored only at the base cost scenario,
so the tuples differed by *membership*, and the report announced **THE RANKING FLIPS** — a
headline finding, manufactured out of a missing row. Stability is now judged only over the
rungs every scenario scored, and rungs missing from any scenario are named as a gap in the
sweep. This is the same class of error as T-113's: at a glance the output looked like a
finding about the models and was a finding about the harness.

**FLOOR-FAIL had to be defended against the reader's eye, not just recorded.** `EvalResult`
already carries `floor_fail`, so one column would have satisfied the schema. It renders in
five places instead — banner above the main table, in the rung's own name, on the savings
cell, in a verdict column, and in §7 with the number — because a reader skimming a
sixteen-column table does read the leftmost cell and does not read the sixteenth.

## Not implemented, and why

Three of the six ablations named in §8.6 — leave-one-family-out, T1 vs T1+T2, and the
graph-feature re-test — are **not rendered**. `EvalResult` (09-interfaces.md §11) has no
field distinguishing an ablation variant from a rung, so those runs cannot be carried in
`docs/results_v2.parquet` at all. The cohort-residual on/off ablation *is* rendered, as
Rung 3 vs Rung 2 in the adoption table, which is the K-1 test. The report names the gap on
its face rather than rendering three empty tables. **Closing it needs a schema field, which
means reopening the §11 freeze — flagged, not patched around.**

The reliability curve (§2 calibration) and the G5 figure (§7) are produced by the eval and
gate paths, not here; `report.py` links whatever is in `docs/figures/` and says **NOT
PRODUCED** when the directory is empty. No matplotlib dependency was added.

## Wiring (Lane D owns `cli.py` and the `Makefile`)

`make report` → `python -m rakshak.cli report`. The subcommand is three lines:

```python
@app.command("report")
def report_cmd(
    results: Path = typer.Option(RESULT_DIR, "--results", help="Scored rung JSONs."),
) -> None:
    """Render docs/results_v2.md + docs/results_v2.parquet from the scored rungs."""
    typer.echo(str(report.write_report(report.read_result_dir(results), root=ROOT)))
```

`write_report` calls `verify_lock` itself, so no guard is needed here; it opens no data and
no split.
